# pt8 — 얻은 단서와 직업의 강점을 써먹는 선택

2026-10-01 작성. pt7의 상태·방어 설명 개선 위에 더한 후보 빌드.

## 목표와 범위

1. **직전에 얻은 성과를 다음 선택에 사용한다.** 검증: 기존 저장의 장부·선제 제압 flag에 따라 대면 선택과 여파 안내가 나타나고 성공·실패 분기가 진행된다.
2. **첫 전투에서 각 직업의 강점으로 적의 행동을 끊는다.** 검증: 버튼의 판정과 실제 행동이 같은 직업 데이터를 사용하고, 기존 피해·행동 취소·반격 보너스 소모를 유지한다.
3. **좁은 화면의 헤더와 판정 영역을 유연하게 배치한다.** 검증: 제한적인 CSS 보완만 반영하며 실제 모바일 육안 검증은 별도로 남긴다.

선택의 결과와 직업별 차이를 더 잘 느끼게 하려는 개발 가설이다. 재미가 검증되었다고 판단하지 않는다. 2장의 장면 수를 늘리거나 새로운 보상·저장 시스템을 도입하지 않는다.

## 변경 내용

- `SCENES.confront`: 이번 모험에서 `ledger`를 얻었으면 장부를 진술과 대조하는 **INT·조사 DC9**, `grip`을 얻었으면 제압의 주도권으로 압박하는 **STR·위협 DC9** 선택을 추가했다. 렌의 정보와 기본 설득·전투 선택은 유지한다.
- 두 새 선택은 성공하면 기존 `peaceful2`와 `ending2`, 실패하면 기존 `combat2`로 이어진다. 이전 회차의 장부 지식만으로는 새 선택이 열리지 않는다.
- `ECHOES.confront`: 장부를 가져온 행동, 매복을 역이용해 제압한 행동이 현재 선택의 기회가 되었다는 안내를 추가했다.
- `LOOTER_DISRUPTS`: 파이터 **STR·운동**, 로그 **DEX·은신**, 위저드 **INT·비전학**으로 첫 전투의 방해 행동을 구분한다. DC12와 성공 시 1d6 피해·적 행동 취소, 실패 시 적 피해 배율 1.3, 기존 반격 보너스 소모는 유지한다. 별도 특수기 횟수는 소비하지 않는다.
- 버튼 이름·기능·성공 확률과 실제 판정·성공/실패 로그가 공통 직업 맵을 사용한다. 새 문구는 한국어·영어를 모두 제공한다.
- 700px 이하에서 헤더와 제어 버튼 줄바꿈, 제어 버튼 높이 최소 44px, 판정 설명과 막대의 최소 너비 완화를 적용했다. 기존 760px 콘텐츠 최대 너비는 유지한다.

## 호환성과 달라지는 난이도

저장 키, 저장 버전 1, 기존 장면 키·flag·엔딩·유물 조건, 진행 복원 형식은 그대로다. 전투 중 임시 상태는 기존처럼 저장하지 않는다. 설문·오류 보고 주소나 전송 방식은 수정하지 않았고 빌드 표기만 pt8로 바뀐다.

직업에 맞는 능력치·숙련을 쓰므로 로그와 위저드의 첫 전투 방해 성공률은 실제로 높아진다. 기본 캐릭터의 d20 기준으로 로그는 45%→70%, 위저드는 40%→70%이며 파이터는 70%로 같다. 2d6에서는 셋 모두 약 92%가 된다. 설명만 바꾼 pt7과 구분해, 다음 관찰에서는 방해 행동만 반복하게 되는지와 전투 긴장감을 확인한다.

## 검증

`node --test tests/*.test.cjs`: **37개 통과**.

- 한국어·영어 각각에서 기존 v1 저장을 `이어서 하기` 버튼으로 복원한다. 장부만·제압만·둘 다·둘 다 없음·렌 정보 보유 조건의 선택 노출 및 여파 문구를 확인한다.
- 실제 선택 버튼 핸들러와 판정 애니메이션 완료 콜백을 실행해, 두 새 선택의 성공이 평화 엔딩·기존 장부 유지로 이어지고 실패가 스컬리 전투로 이어지는지 확인한다.
- 두 주사위 규칙과 세 직업에서 표시된 이름·기능·확률을 확인한다. 경계값 주사위로 훈련된 주 능력치의 성공·실패, 공격 및 회복 취소, 추가 피해, 반격 보너스 소모, 특수기 횟수 보존을 확인한다.
- 기존 pt7의 전투 방어·HP 표시·언어 변경 시 상태 보존 및 내장 스크립트 문법 테스트도 통과한다.

이 검증은 React 상태를 대체하는 Node 테스트다. DOM 효과, 실제 기기 저장소, 모바일 글자 잘림·터치, 시각적 줄바꿈을 검증하는 브라우저 종단 테스트는 아니다. 설문을 새로 제출하거나 유료 세션을 시작하지 않았다.
