## 첫 언어 결정

두 HTML 파일에서 동일한 `resolveInitialLanguage()`를 사용한다. 독립적인 편지 진입 페이지가 추가 외부 파일에 의존하지 않도록 같은 함수를 인라인으로 두고, 동일한 입력 행렬로 동작을 검증한다.

1. URL의 유효한 `?lang=en` 또는 `?lang=ko`.
2. `aduventure_lang`에 JSON으로 저장된 유효한 `en` 또는 `ko`.
3. 브라우저의 최우선 언어가 `ko`로 시작하면 한국어, 그 외에는 영어.
4. `navigator` 자체가 없으면 한국어.

브라우저 언어는 `navigator.languages`의 첫 번째 비어 있지 않은 문자열을 사용하고, 없으면 `navigator.language`를 사용한다. 대소문자는 구분하지 않는다. 예를 들어 `['en-US', 'ko-KR']`는 영어, `['ko-KR', 'en-US']`는 한국어다. `navigator`는 있지만 쓸 수 있는 언어가 없으면 영어다.

- URL·저장 값이 잘못되었거나 빈 값이면 다음 우선순위로 넘어간다.
- 유효한 URL 언어는 기존 JSON 저장 형식으로 저장한다. 저장소 쓰기가 차단돼도 선택한 언어로 열린다. URL 언어가 없을 때 브라우저 자동 선택만으로 기존 저장 값을 덮어쓰지는 않는다.
- `index.html`은 최초 상태 생성 시에만 언어를 결정한다. 이후 언어 토글·재렌더링이 초기 언어로 되돌아가지 않는다. URL에 `?lang=en`이 남아 있는 상태로 새로고침하면 요청한 우선순위에 따라 URL 값이 다시 우선한다.
- `letter.html`은 telemetry 전송과 별개로 먼저 언어를 결정한 뒤 `./?lang=en#returned-letter` 또는 `./?lang=ko#returned-letter`로 즉시 이동한다. 저장소가 막혀도 이 쿼리로 본편에 언어가 전달된다.
- 두 페이지의 `page_open.lang`은 해당 페이지에서 결정한 언어다. 편지 페이지에서 fetch가 없거나 실패하거나 끝나지 않아도 선택한 언어가 이동 URL에 남는다.
- JavaScript가 꺼진 경우의 기존 meta refresh 및 한·영 수동 링크는 유지한다. 자동 언어 판별과 쿼리 전달은 JavaScript 실행 경로에서 처리한다.
- pt49의 이벤트 형식·익명 ID·중복 방지 규칙은 유지한다. 편지 페이지를 거쳐 본편을 열면 페이지별 이벤트가 하나씩 발생하므로 방문 집계는 계속 `page`를 구분한다.

## 다회차 설문

기존 PlaytestFeedback 질문을 모두 유지하고 다음 항목을 한·영으로 덧붙였다. 목표는 첫 플레이 완료 여부와 별개로, 재미 때문에 바로 다시 할 의사가 생겼는지와 그 이유를 확인하는 것이다. 정답이나 호의적인 답을 요구하지 않는다. 새 항목은 선택 응답이다.

| `answers` 키 | 질문 / 값 |
|---|---|
| `replayWant` | 끝나거나 멈춘 뒤 바로 한 판 더 하고 싶었는가. `now`(지금 바로), `later`(나중에), `no`(아니), 미응답 `""` |
| `replayWhy` | 그 이유. 문자열 |
| `replayDiff` | 다시 한다면 무엇을 다르게 하겠는가. 문자열 |
| `funOne` | 더 재미있으려면 딱 하나만 바꾼다면. 문자열 |
| `replayDrivers` | 복수 선택 배열. 아래 표의 고정 코드를 사용하며 미응답은 `[]` |
| `replayDriversOther` | 기타 직접 입력. `other`가 선택되지 않으면 전송·복사·내보내기에서 `""` |
| `comeBack` | 내일 또 올 것 같은가. 정수 `1`~`5`, 미응답 `""`. 1은 전혀 아니다, 5는 매우 그렇다 |
| `pay3` | 정식판이 US$3(약 4,000원)면 구매하겠는가. `yes`, `maybe`, `no`, 미응답 `""` |
| `tester` | 레딧 아이디 또는 닉네임. 선택 입력 문자열, 유료 테스터 보상 확인용 |

| `replayDrivers` 값 | 한국어 | 영어 |
|---|---|---|
| `endings` | 다른 엔딩 | Different endings |
| `class_path` | 다른 직업·경로 | Different classes or routes |
| `harder` | 더 어려운 모드 | A harder mode |
| `secrets` | 숨은 비밀·유물 | Hidden secrets or artifacts |
| `daily` | 오늘의 도전 | Daily challenges |
| `shorter` | 더 짧은 한 판 | Shorter runs |
| `other` | 기타 | Other |

선택 코드는 언어 전환과 무관하게 유지된다. 설문을 연 상태에서 언어를 바꿔도 입력을 보존한다. `tester`는 설문 응답에만 포함하며 자동 페이지 telemetry나 게임 저장에 추가하지 않는다.

### 기존 전송 형식과 제출 규칙

- 기존 `type: "playtest_feedback"`, `build`, `lang`, `reached`, `stop`, `minutes`, `at`, `answers`를 유지한다.
- `text`에는 기존 요약 줄을 그대로 남기고 `[replayWant]`, `[replayWhy]`, `[replayDiff]`, `[funOne]`, `[replayDrivers]`, `[replayDriversOther]`, `[comeBack]`, `[pay3]`, `[tester]` 줄을 덧붙인다. 복수 선택은 쉼표로 구분한 코드를 기록한다.
- `extra`에는 기존처럼 피드백 전체 객체의 JSON 문자열을 넣는다. 새 값은 최상위 `answers`와 파싱한 `extra.answers`에 동일하게 담긴다. 기존 `choice`·`quit` 요약 키도 유지한다.
- 서버 전송·클립보드 복사·TXT 내보내기는 같은 요약 함수를 사용한다.
- 기존 질문만 답해도, 새 질문만 답해도 제출할 수 있다. 완전히 빈 응답은 기존처럼 막는다. 기존 질문에서 ‘있었다’를 골랐지만 위치와 이유를 모두 비우면 새 응답이 있어도 제출을 막는 기존 규칙을 유지한다.
- 모든 장 엔딩의 접힌 정리 바깥에 `30초 설문` / `30-second survey` 버튼을 추가했다. 첫 판 1장에서도 보이며 현재 장면을 유지한 채 기존 PlaytestFeedback을 연다.

## 검증

- 기준 커밋에서 `node --test tests/*.test.cjs`: **354개 통과**.
- 새 요구사항 테스트가 변경 전 실패함을 확인한 뒤 구현했다.
- 수정 후 `node --test tests/*.test.cjs`: **370개 통과, 실패 0** (기존 354 + 신규 16).
- 언어 테스트 7개: 두 페이지에 각각 18가지 우선순위 사례, URL 저장 및 후속 방문, 차단된 저장소에서 편지→본편 전달, telemetry 실패 시 이동, 언어 토글과 중복 방지, 두 정적 제목의 빌드 일치.
- 설문 테스트 9개: 한·영 실제 입력과 전송 payload, 기존 응답 보존, 새 답변만 제출, 기존 유효성 검사, 7개 복수 선택과 기타 해제, 언어 변경 중 값 보존, 복사 내용, 첫 판 엔딩 버튼으로 실제 모달 열기.
- pt49의 기존 redirect 테스트는 언어 쿼리를 유지하는 새 URL을 기대하도록 수정했다. 기존 검증 항목은 제거하지 않았다.
- 기준 커밋과 게임 장면·선택지·결말·규칙 데이터 영역을 비교해 동일함을 확인했다. `git diff --check`도 통과했다.

자동 검증은 실제 앱 스크립트와 핸들러를 Node VM에서 실행한다. 실제 브라우저 실기와 운영 GAS 수신, 사람의 재플레이 의향은 별도 확인 대상이며 이 테스트 결과로 입증하지 않는다.
