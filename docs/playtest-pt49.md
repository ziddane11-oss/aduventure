## 화면 변경

1. 1장 엔딩의 `pauseOk` 안내(여기서 멈춰도 됨 / 나중에 이어할 수 있음)만 숨긴다. 엔딩 저장, 2장 계속 버튼, 재시작 버튼은 유지한다. 2장 이후에는 기존 첫 회차 표시 조건을 그대로 적용하며, 원래 안내가 없던 최종 엔딩에도 새 안내를 추가하지 않는다.
2. 2장 첫 본문의 베른 증언과 후속 훅을 1장 엔딩 마지막 문단으로 옮긴다. 모든 1장 결말 분기에서 접힌 정리 영역 바깥에 표시한다.
   - 한국어: “뒤에서 맞았네. 검은 코트… 항구 쪽으로 달아났지.” / “등대를 끈 자는 사람이다. 그리고 아직 마을에 있다.”
   - 영어: “Struck from behind. A black coat… ran off toward the harbor.” / “Whoever put out the light was a person. And they're still in town.”
   - 베른이 다음 날 아침 깨어나는 맥락도 함께 이동한다. 2장 도입은 베른의 침상과 아침 항구를 짧게 보여 주며 증언을 반복하지 않는다. 부두 이동·기억 질문의 선택지와 조건은 그대로다.
3. 정적 페이지 제목과 `BUILD`를 pt49로 맞춘다. 새로 표시하는 서사는 한국어·영어를 함께 제공한다.

## 페이지 열림 telemetry

기존 GAS 수신 경로와 `type: "telemetry"`, `text: "page_open"`, JSON 문자열 `extra` 형식을 사용한다. 이벤트 이름은 언어와 무관하게 고정한다.

| 진입 | `scene` / `extra.page` | `extra.entry` | 발생 시점 |
|---|---|---|---|
| 본편 시작 | `index.html` | `main` | 첫 화면 마운트 시 1회 |
| 편지 사건 직접 진입 | `index.html` | `returned-letter` | `#returned-letter`로 첫 화면 마운트 시 1회 |
| 서명 없는 명령 직접 진입 | `index.html` | `unsigned-order` | `#unsigned-order`로 첫 화면 마운트 시 1회 |
| 편지 공유 주소 | `letter.html` | `returned-letter` | 본편으로 자동 이동하기 전 1회 |

`extra` 공통 필드는 `v: 1`, `build`, `page`, `entry`, `lang`, `player_id`, `visit_id`다. `who`에는 같은 익명 `player_id`를 넣는다. `lang`은 페이지를 열 때 저장된 언어(`ko` / `en`, 기본 `ko`)다. 임의 해시는 `main`으로 분류하며 원문을 전송하지 않는다.

- 캐릭터 생성이나 이어하기 클릭 전에도 기록한다. 새 회차를 만들거나 기존 저장을 이어하지 않으며 `run_id`를 넣지 않는다.
- 본편의 언어 전환, 사건 해시 전환, 재렌더링, 이어하기로는 추가 `page_open`을 보내지 않는다. 새로고침은 새 `visit_id`를 만든다. 본편의 방문 ID는 기존 선택 telemetry에도 사용된다.
- `letter.html`은 기존 `aduventure_anon_player`의 JSON 저장 형식을 읽고, 없거나 잘못되었으면 새 익명 ID를 저장한다. 같은 브라우저에서 저장소가 허용되면 이동 후 본편도 같은 ID를 사용한다. 게임·사건 저장 내용, 캐릭터 이름, 원시 URL·검색 문자열·referrer는 추가하지 않는다.
- 두 페이지 모두 `keepalive: true`로 전송한다. 편지 페이지는 응답을 기다리지 않고 즉시 `./#returned-letter`로 이동한다. JavaScript가 꺼졌을 때만 meta refresh를 사용하며 한·영 수동 링크도 유지한다.
- 저장소 접근 차단, 손상된 저장 값, fetch 부재·동기 예외·비동기 실패가 게임 진입이나 자동 이동을 막지 않는다. 저장소가 막힌 페이지 사이에는 같은 익명 사용자를 연결할 수 없다.
- 편지 페이지는 React 없이 동작하도록 작은 스크립트를 독립적으로 둔다. 테스트에서 두 페이지의 빌드·수신 주소·익명 ID 형식 일치를 확인한다.

### 집계 시 주의

`letter.html`을 거쳐 본편이 열리면 **서로 다른 두 페이지의 `page_open`이 총 2개** 발생한다. 전체 행 수를 방문자 수로 해석하지 않는다. 본편 진입 수는 `page === "index.html"`로, 공유 주소 진입 수는 `page === "letter.html"`로 나누어 센다. `player_id`도 브라우저 저장소 기반 익명 식별자이며 실제 사람 수를 보장하지 않는다.

전송은 최선 노력 방식이다. 네트워크 차단이나 페이지 종료로 수신이 누락될 수 있으며, 이 이벤트만으로 플레이 시작·완료 여부를 판단하지 않는다.
