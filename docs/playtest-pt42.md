# pt42 — 반송된 편지 / The Returned Letter

## 목적

“내가 쓴 문장이 다음 역할의 행동을 제한한다”는 장치가 독립된 재미를 만드는지 확인하는 짧은 사건이다. 본편 첫 화면의 **새 사건 미리보기 · 반송된 편지**, 또는 아래 링크로 입장한다.

https://ziddane11-oss.github.io/aduventure/#returned-letter

본편의 기존 세이브와 회차 번호는 사용하지 않는다. 언어 설정만 공유한다. 본편으로 돌아가기와 다음 입장 시 이어 하기를 지원한다.

## 플레이 흐름

1. 기록관: 확인된 사실 세 개와 접수 규정을 읽고 세 문장을 선택한다. 직접 이름을 적어 서명한다.
2. 배달부 핍: 같은 보고서가 출입 근거가 된다. 배달증, 실명 증인, 별지 접수로 이용할 수 있는 창구가 달라진다. 막힌 길을 누르면 정확한 근거 문장과 실제 서명을 보여 준다.
3. 베른의 신청: 살아 있지만 명부에 없는 사람의 신청서를 읽는다. 오전의 ‘별지 접수’ 선택에 따라 신청서가 이미 접수되었거나 여전히 반송된 상태임을 확인한다.
4. 기록관: 원문 유지 / 문장별 정정 / 판단 유보를 선택한다. 최초 원문과 서명은 남는다.
5. 결과: 자격, 이름 공개, 신청 접수의 실제 결과를 보여 준다. 이전 문장으로 다시 시작해 다른 선택을 비교할 수 있다.

## 규칙

| 문장 | 즉시 생기는 효과 |
| --- | --- |
| 배달을 거부했다 | 배달 자격 정지 |
| 배달은 지연되었다 | 배달 자격 유지 |
| 베른의 이름을 공개한다 | 실명 증인 창구 허용, 공개 이력 발생 |
| 수취인의 이름을 봉인한다 | 이름 보호, 공개 명부로 신원 확인 불가 |
| 별지를 첨부해 접수한다 | 열람 창구 허용, 신청이 정식 심사 대상이 됨 |
| 별지를 배달부에게 돌려준다 | 이 보고서에 접수되지 않음 |

- 모든 조합에서 서류를 다시 펼쳐 보는 길이 열린다. 무작위 판정이나 강제 실패가 없다.
- 처음부터 신중하게 작성하면 자격과 비공개 상태를 유지하면서 신청을 접수할 수 있다. 모든 선택을 비극으로 수렴시키지 않는다.
- 이름 공개와 접수의 과거는 정정으로 소급 삭제되지 않는다. 접수된 원본을 나중에 돌려주어도 접수 이력과 심사 대상 지위는 남는다.
- 유보는 정지된 배달 자격만 임시 회복한다. 이름 공개나 미접수 상태까지 자동으로 고치지 않는다.
- 처음부터 제시한 “첨부지는 본문과 같은 효력”이 결말에서 다시 작동한다. 숨겨 둔 규칙으로 플레이어를 벌하지 않는다.
- 재플레이는 별도 체험 안에서만 새 시도를 시작한다. 본편 데이터와 이전 체험 비교 기록은 보존한다.

## 구현 범위

- 한·영 전체 번역, 문장 ID 기반 상태 전이.
- 별도 저장 키: aduventure_own_record_v1. 알려진 버전/단계/선택지만 복원한다.
- 동작 감소 환경에서는 전환 애니메이션 생략.
- 좁은 화면에서는 출입 선택지가 한 열로 바뀐다.
- 선택 의미는 버튼에 명시하고, 원본 문장을 그대로 출입 근거로 사용한다.
- 네트워크나 생성형 AI 호출 없이 동작한다. 새 분석 이벤트를 전송하지 않는다.

## 검증

자동 검사:
- 기존 309개 + 새 8개 = 317개 통과.
- 처음 서명할 수 있는 8개 조합 모두의 출입 권한과 탈출 경로.
- 순서가 잘못된 행동/불완전 서명 차단.
- 정정의 실제 효과와 원문 불변성.
- 유지·유보·정정 차이, 공개 이력과 접수 이력 보존.
- 다시 읽기 중 정정안 저장, 단계별 복원, 잘못된 저장 처리.
- 실제 컴포넌트 버튼으로 서명 → 차단 사유 → 별지 → 검토 → 결말 이동.
- 언어 전환과 본편 저장 보존.

공개 브라우저에서 pt42의 서명 → 막힌 길과 원문 근거 → 별지 → 정정 결말을 완주했다. 영어 전환과 새로고침으로 같은 서명/단계를 복원했다. 두 번째 플레이에서 지연·봉인·접수를 골라 배달증과 열람 창구가 열리는 것, 처음 서명한 시점의 접수 사실, 원문 유지 결말을 확인했다. 본편으로 돌아가 기존 이어하기가 유지되는 것도 확인했다.

pt42.1은 첫 화면 버튼 입장 시 주소도 사건 주소로 유지하고, 주소의 사건 표지가 바뀌면 화면을 동기화한다. 버튼 입장 후 새로고침이 본편 화면으로 돌아가던 문제의 재현 검사를 추가했다.

자동 검사와 브라우저 기능 확인은 사람의 재미 검증 결과가 아니다. 모바일 실기기는 아직 확인하지 않았다.

## 소규모 사람 테스트

장르를 좋아하는 사람 6명에게 첫 플레이 동안 설명하지 않고 관찰한다. 이 숫자는 방향을 잡기 위한 소규모 질적 테스트이며 시장 통계가 아니다. 이 빌드의 목표 플레이 시간은 5~10분이지만 실제 사람의 소요 시간은 아직 측정하지 않았다.

플레이 후 아래 순서로 질문한다. “혁신적인가 / 천재 같은가”를 먼저 묻지 않는다.

1. 누구에게 이 게임을 설명한다면 방금 어떤 일이 일어났다고 말하겠는가?
2. 막힌 길이 왜 막혔다고 생각했는가? 화면에서 근거를 짚어 달라.
3. 처음 본 내용 중 나중에 의미가 달라진 것은 무엇인가?
4. 정정 화면에서 바꾸고 싶었던 문장과 그 이유는?
5. 다시 한다면 무엇을 바꾸겠는가? 실제로 다시 눌러 보는가?

관찰할 신호:
- 유도 없이 자신의 문장과 잠긴 길을 연결한다.
- 접수 규정 또는 자신의 첨부 선택을 스스로 회상한다.
- 결과가 달라질 것이라는 구체적 예측을 갖고 재플레이한다.
- 정정의 결과를 보기 전에 적어도 한 번 문장을 비교한다.

설명을 듣고 나서만 장치를 이해하거나, 대부분 모든 문장을 기계적으로 바꾸고 끝내면 도입/피드백을 다시 다듬는다. 이 실험의 반응을 확인하기 전에는 사건 수를 늘리지 않는다. “천재 같다”는 평가는 제작 목표이며 현재 검증된 결과가 아니다.
