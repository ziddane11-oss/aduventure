# pt44 — 이름을 공개한 대가를 정정 전에 겪는다

## 바뀐 경험

검토 결과: 「반송된 편지」의 2번 문장(수취인 공개 범위)은 '공개'를 고르면 증인 창구가 열리고, 대가는 엔딩 한 줄뿐이었다. 메커니즘상 '공개'가 사실상 공짜라 선택이 딜레마가 되지 않았다. 외부 플레이어 피드백("갈래가 많아 아무거나 고를 때도 있었다")과도 맞닿아 있다.

- 다음 날 아침(기록관 창구) 첫 문단에 게시판 공시를 보여 준다.
  - 공개: 베른의 이름이 붙었고, 누군가 손톱으로 그 이름 아래에 줄을 그었다.
  - 봉인: 수취인 칸에 붉은 봉인 표시만 있다.
- 핍의 시점, 베른을 만나는 장면에서 모든 경로에 베른의 반응을 넣는다.
  - 공개: 오는 길에 세 사람이 알아봤고 한 사람이 끝까지 따라왔다.
  - 봉인: 아무도 알아보지 못했다. 핍의 부탁이 받아들여졌다는 것을 안다.
- 출입 판정·세이브 형식·결과 계산은 그대로다. 대가는 서사로만 추가했다(pt43 원칙대로 서명 전에는 알려 주지 않는다).
- 처리 결과 화면에 **공유 버튼**을 추가했다. 효력이 남은 세 문장, 처리 도장, 결과 세 줄, 초대 문장, 주소를 담는다. Web Share API가 있으면 공유 시트를, 없으면 클립보드 복사를 쓴다. 서명(실명일 수 있음)은 넣지 않는다.
- 단독 진입 주소 `letter.html`을 추가했다. 링크 미리보기용 메타 태그를 두고 `./#returned-letter`로 바로 넘긴다. 공유·페스티벌 출품 링크로 쓴다.

## 검증

- 새 검사 2개: 공개/봉인이 다음 날 아침과 베른 장면(배달증·사본 경로)에서 서로 다른 문장으로 보이는지, 서명 전 화면에 새 문장이 미리 새지 않는지(한·영). 공유 문구가 정정 후 효력 문장·결과·주소를 담고, 서명은 빠지며, 영어에 한국어가 섞이지 않는지.
- 기존 318개 + 새 2개 = 320개 통과.
- 로컬 브라우저(390px)로 `letter.html` → 체험 진입, 공개(한국어)/봉인(영어) 끝까지 진행, 공유 버튼으로 클립보드 복사 확인. 가로 스크롤 없음, 페이지 오류 없음.

## 이번에 사람에게 확인할 것

처음 보는 플레이어 3명에게 `letter.html`만 건넨다. 2번 문장을 고른 이유를 서명 직후 묻고, 다음 날 게시판 장면 뒤에 다시 묻는다. "아무거나 골랐다"는 대답이 나오는 문장이 있는지 기록한다. 공유 버튼을 누르는지, 누른다면 어디에 붙여 넣는지도 본다.
